## 1. 设计任务与系统边界

本设计针对四轮麦克纳姆轮底盘的速度跟踪、轨迹预测及异常工况停机问题。在原 STM32F407 工程上保留四个 M3508 电机、C620 电调、CAN 通信和速度环控制的结构，增加电脑端 C 语言实验程序，把参数设置、运动学解算、电机响应模拟、状态监测、数据记录和结果分析连成完整实验流程。

底盘具有三自由度速度指令，四个车轮相互耦合。轮速限幅、执行器惯性、负载、轮地滑移及通信故障均可能使实际轨迹偏离理想轨迹，因此不能仅用“速度乘时间”代替完整预测。系统通过同一组实验条件同时计算理想轨迹和含非理想因素的轨迹，比较偏差，并用故障注入检查软件保护逻辑。

电脑端输出属于模型仿真结果。固件提供实物实验的控制和采集接口；在未连接底盘完成校准、时序检查和实测对比之前，仿真结果不能作为实车精度或停机距离的证明。

## 2. 原工程复用与软件架构

应用目录统一命名为 `JHY`。`Core` 与 `Drivers` 分别承担外设初始化和芯片驱动，`JHY` 保存底盘运动学、PID 和电机驱动，`Simulation` 保存电脑端 C 程序及实验配置，`docs` 保存设计文档。第三方芯片库保留原版权声明。

电脑程序直接编译 `JHY/Src/alg_mecanum_wheel_chassis.c` 中的 `Mecanum_Wheel_Inverse_Kinematics`，不另写一套名称相同但实现不同的逆解。运动学头文件去除无用硬件依赖后，同一份源码可以同时供 ARM 固件和电脑程序使用。固件速度控制器（输出电流指令）和电脑端等效电机控制器的量纲不同，电脑端 PID 系数不能直接写入实物控制器。

电脑端数据流为：读取并校验配置 → 应用到时事件 → 安全检查 → 逆运动学与轮速缩放 → 四轮闭环与等效电机响应 → 滑移修正 → 正运动学 → 位姿积分 → CSV 与状态输出 → 指标及报告生成。异常状态进入停机分支，控制输出归零，但继续记录速度衰减，保留故障后的分析数据。

固件由定时中断承担周期控制及联锁检查，主循环处理串口命令和遥测发送。控制中断不执行报告排版或文件写入，避免输出阻塞干扰控制周期。实测数据保存由电脑串口接收工具完成，不能把单片机内存中的最新值等同于已经持久化保存的数据文件。

## 3. 数学模型与算法

### 3.1 坐标、轮序及单位

轮序固定为左前 LF、左后 LB、右后 RB、右前 RF。几何参数 `a`、`b` 分别为半轮距和半轴距，`R` 为轮半径，令 `L=a+b`。速度使用 m/s，角速度使用 rad/s，位置使用 m，角度使用 rad，时间使用 s。

程序沿用原代码的输入变量 `vx`、`vy`、`omega` 和矩阵符号。原注释把 x 标为向右、y 标为向前，电机安装方向和滚子方向仍需通过架空实验确定。仿真证明的是该代数模型的内部一致性，不能据此断言正 `vx` 在实车上必然向右；必须逐轮检查 CAN ID、反馈正号和正转方向，再核对平移与旋转的物理方向。固件电机坐标与底盘坐标之间的反号映射也应单独记录。

### 3.2 逆运动学与防饱和

使用原程序的四轮逆解：

```text
ωLF = (vx - vy - L·omega) / R
ωLB = (vx + vy - L·omega) / R
ωRB = (vx - vy + L·omega) / R
ωRF = (vx + vy + L·omega) / R
```

若 `ωpeak=max(|ωLF|,|ωLB|,|ωRB|,|ωRF|)` 超过允许值 `ωmax`，统一乘以 `ωmax/ωpeak`。这一缩放在理想运动学模型下保留三轴速度的比例关系；它不能消除真实轮胎打滑或驱动力不均匀造成的方向误差。

### 3.3 正运动学与轨迹

与上述矩阵配对的正运动学为：

```text
vx    = R·(ωLF + ωLB + ωRB + ωRF) / 4
vy    = R·(-ωLF + ωLB - ωRB + ωRF) / 4
omega = R·(-ωLF - ωLB + ωRB + ωRF) / (4L)
```

在 `R>0`、`L>0` 且未限幅时，先逆解再正解应恢复输入速度。限幅时应恢复缩放后的速度，这是运动学自检的依据。它属于公式一致性检查，不是与实物独立测量的精度验证。

世界坐标位姿为 `(x,y,theta)`，使用二维旋转将机体速度变为世界速度：

```text
dx/dt     = cos(theta)·vx - sin(theta)·vy
dy/dt     = sin(theta)·vx + cos(theta)·vy
dtheta/dt = omega
```

理想分支保留限幅后的任务轮速，不包含响应迟滞和滑移；模拟分支使用电机状态及滑移后的有效轮速。即使发生故障，理想分支仍继续计算原任务的计划轨迹，而模拟分支进入停机状态，因此故障工况的轨迹误差还包含任务中断的偏离。CSV 的四轮 `target` 列表示联锁后实际施加的轮速目标，故障后记录为零；它与继续运动的任务参考用途不同。故障后有惯性的模拟轮速仍可能不为零，输出归零不表示车辆瞬时静止。

### 3.4 执行器与闭环控制

四轮分别设置速度环。第 i 轮的测量为 `mi=ωi+noise·ξi`，其中 `ξi` 为区间 [-1,1] 的均匀伪随机量。误差 `ei=ωtarget,i-mi`，积分候选限制在 [-1,1]，控制器使用稳态前馈、比例、积分及测量微分项：

```text
u_raw = ωtarget / K + Kp·e + Ki·I - Kd·(m-m_previous)/h
u     = clamp(u_raw, -1, 1)
dω/dt = [K·(1-load)·u - ω] / tau
ωground = (1-slip)·ω
```

当输出饱和且误差推动进一步饱和时停止累积积分。电机状态使用显式欧拉更新；世界坐标位置使用本步中点航向进行积分。`load` 为驱动增益折减比例，`slip` 为四轮统一的有效轮速折减比例。电流估算 `Iest=|u|·Imax`，教学温度模型为 `dT/dt=0.025·Iest²-0.08·(T-Ta)`。这些变量均在电脑端定义，不能将等效控制量、估算电流或温度解释为经过实物标定的测量值。

模型刻意保留低阶结构，使参数变化对速度跟踪及轨迹偏差的影响可以解释。原工程的逆动力学力矩分配接口仍可供后续研究使用，但当前速度仿真不构成完整车体刚体动力学、接触力或电气热模型。

### 3.5 误差与可靠性指标

第 k 个采样点的平面轨迹误差为 `ep(k)=sqrt((xsim-xref)^2+(ysim-yref)^2)`，程序采用时间加权均方根误差 `RMSEp=sqrt(sum(ep(k)^2·hk)/duration)`，使不足完整步长的最后一步得到适当权重。各轮目标与响应可由 CSV 相减分析。偏航指标采用未归一化的累计航向差；它保留转过整周的差异，不能直接解释为限制在 [-π,π] 的最终朝向误差。

步长检查保持物理参数和事件时间相同，关闭随机噪声后分别以 `dt` 和 `dt/2` 计算终点位置及累计航向，输出两次终点位置的平面距离和航向差绝对值。这一附加比较与带噪声的主实验分开进行，避免随机采样次数变化混入数值敏感性指标。步长差值较小只说明该模型在这两种分辨率下接近；它还可能包含事件执行时间量化的影响，不能替代真实底盘的准确性验证，也不能当作统计置信区间。

## 4. 参数、数据与可重复实验

| 参数类别 | 含义与设定原则 |
|---|---|
| 原底盘几何 | `a=0.215 m`、`b=0.2215 m`、`R=0.077 m`，沿用所给代码；实物应重新量测 |
| 轮速约束 | 默认最大轮速 15 rad/s，需结合实验空间和底盘条件设置 |
| 采样与时长 | 默认 `duration=12 s`、`dt=0.01 s`；步长范围 0.0001～0.05 s，时长不超过 600 s，样本数量不超过 100 万 |
| 初始运动指令 | 默认 `vx=0.25 m/s`、`vy=0.35 m/s`、`omega=0.2 rad/s` |
| 控制参数 | 默认 `Kp=0.08`、`Ki=0.6`、`Kd=0.0004`；时间常数 `tau=0.12 s`、增益 `K=20 rad/s`；要求 `tau≥5dt` |
| 环境扰动 | 默认负载折减 0.08、滑移 0、均匀噪声幅度 0.02 rad/s；建议先做关闭噪声的基线 |
| 仿真保护参数 | 默认最高温度 65°C、反馈超时 0.1 s、估算电流上限 8 A，超速门限为最大轮速的 1.2 倍 |
| 随机种子 | 默认 2026；固定种子可重复同一离散仿真实验，多个种子用于敏感性分析 |

建议实验顺序为：零指令与初始状态检查、单轴平移、纯旋转、复合运动及轮速饱和、滑移与负载对比、运行中参数调整，最后进行通信超时、过温和急停注入。每次只改变有意研究的变量，使用独立输出目录，保存配置、事件文件和生成报告，避免覆盖导致实验条件无法追溯。

事件文件采用 `时间,键,值` 的三列格式，按时间升序排列，每次最多 256 条。可调整 `vx`、`vy`、`omega`、`kp`、`ki`、`kd`、`slip`，或注入掉线、过温、急停。例如 `2,vx,0.4` 在第 2 秒改变 x 轴指令，`4,disconnect,1` 模拟 LF 失联，`6,estop,1` 注入急停；事件在首次达到该时间的控制步起点生效，因此执行时间量化误差小于一个步长。

CSV 共 50 列，记录时间、指令、三种位姿、误差、滑移、限幅、保护状态及每轮的目标、响应、测量、控制量、估算电流、温度、反馈年龄和在线标志。里程计轨迹由带噪声编码器轮速积分，模拟真实轨迹由滑移后的轮速积分，可据此观察编码器无法单独识别滑移的现象。测量值来自步初采样，响应速度、位姿、温度和 CSV 时间戳来自步末；首次故障时间则表示检测到故障的控制步起点，读取文件时需留意这一采样顺序。结果目录同时提供机器可读取的 `summary.json`、便于交流的 `report.md`，以及本次输入快照 `used_config.cfg` 和 `used_events.csv`。报告中的结论必须能由对应 CSV 及配置复算。

## 5. 实物实验系统、采集与安全流程

### 5.1 实验系统搭建

系统由 STM32F407 主控、四个 M3508/C620、适配电源、独立急停、CAN 收发器及总线、串口转接器和电脑组成。CAN 端接、供电电压、额定电流和线缆能力必须按实际器件资料及实验室规定核对，不能只凭仿真参数选型。主控 GPIO 不能直接接 CAN_H/CAN_L。

现有工程 CAN1 使用 PD0 接收、PD1 发送，按 42 MHz 外设时钟、3 分频及 14 个时间量子得到 1 Mbps；USART1 使用 PB7 接收、PA9 发送，配置为 420000 baud、8 位数据、无校验、1 位停止位。接线前应再次核对实际开发板引脚与工程配置。CAN 反馈 ID 分配为 0x201、0x202、0x203、0x204，依次对应 LF、LB、RB、RF；控制帧和反馈帧由原驱动收发。

### 5.2 标定与采集正确性

先断开动力电源检查机械固定、轮子滚子方向、线束和急停，再架空底盘上控制电源。保持未使能状态，确认四轮反馈完整且无异常温度。逐轮给予低速指令，核对轮号、正负号和编码器方向；再次核对平移及自转方向，完成后才允许受控落地测试。

电机反馈的转速先由 rpm 转为 rad/s，再除减速比，得到输出轴角速度；原配置减速比为 `3591/187`。编码器多圈推算依赖连续采样，长时间丢帧或首次状态错误可能造成圈数误判，因此应在静止条件建立初值，并记录通信异常。电流原始计数不等于 N·m，未经转矩常数、减速效率和负载标定，不应在报告中直接称为实测扭矩。

固件每 1 ms 检查联锁并更新控制，每 20 ms 形成一条遥测快照，经 16 槽环形队列由主循环调用 USART DMA 发送。遥测共 26 列：毫秒时间戳、使能、故障位、丢弃数、CAN 错误数、命令错误数，以及四轮目标速度、反馈速度、原始电流计数、温度和反馈年龄。队列满时增加丢弃数，因此串口记录并非无条件完整；要结合 `dropped` 判断数据质量。CSV 表头启动时发送，并约每 5 s 重发一次，便于运行中开始采集。

电脑可使用 `tools/Capture-Telemetry.ps1` 以匹配串口参数只读采集并保存 CSV，先保留完整原始文件，再根据字段解析。检查时间戳单调性、采样间隔、行格式和丢弃计数；用静止数据检查零偏，用定速段检查单位及符号，用外部尺量或定位设备获取独立位移。若缺少独立位姿测量，只能评价轮速跟踪和里程计内部一致性，不能声称测得真实轨迹误差。

### 5.3 保护与操作步骤

按“参数校验 → 通信完整 → 无故障 → 人工使能 → 小速度试运行”顺序进行。调整几何、保护阈值或接线后，先停机再重新检查。通信掉线、过温、无效指令或急停应使四轮控制输出归零，并保留故障原因；恢复通信后也必须确认安全条件，不应依靠重新收到数据就自动恢复运动。

固件默认未使能。文本命令以换行结束：`ARM` 检查条件后使能并清零目标；`SET vx vy wz` 设置运动指令；`KEEP` 更新命令心跳；`STOP` 解除使能；`ESTOP` 锁存软件急停；`RESET` 在未使能状态重新检查当前故障。`PID kp ki kd` 与 `GEOM a b R` 仅在停机时允许修改。使能后需至少每 500 ms 发送一次 `KEEP` 或 `SET`，否则命令超时停机。

固件反馈超时门限为 100 ms，温度门限 70°C，实测轮速超过允许最大轮速的 1.2 倍也会触发保护。故障位可组合：1 为离线，2 为过温，4 为超速，8 为非法值或指令，16 为命令超时，32 为软件急停，64 为 CAN 发送错误。仿真与固件阈值属于两个配置域，不能因二者都含过温保护就认为它们完全相同；具体值应以本次实验配置及固件版本为准。

先用电脑仿真验证保护分支。实物故障测试优先在架空、低能量条件实施，不用人为加热电机制造危险温度，也不在车辆高速运行时直接拔插动力线。现场至少一人可立即操作独立硬件急停，测试区域留出制动空间，结束后保存数据、解除使能并切断动力电源。软件零输出不能代替硬件断电急停或机械防护。

## 6. 工具选择、验证与局限性

采用标准 C 语言实现计算和文件处理，便于与原嵌入式代码共享运动学。电脑端 GCC 可快速检查算法、边界和文件输出；ARM GCC、CMake 和 Ninja 用于固件构建；CSV 与 JSON 便于用表格或绘图工具复核，Markdown 和 Word 文档便于报告编辑与交流。编译通过说明源码可构建，自检通过说明覆盖的算法条件符合预期，二者都不等于实物系统已验收。

验证至少包括正逆解往返、纯平移与纯旋转、等比例限幅、非法参数拒绝、固定种子可重复性、事件调整、掉线/过温/急停后的零输出，以及报告追加/删除/替换的内容检查。故障测试还要观察停机后的速度衰减与日志连续性，不能只查看最终状态文字。

当前模型没有完整描述整车质量分布、轮胎和滚子接触、地面局部摩擦、弹性振动、电池电压变化、CAN 调度延迟和真实电机热过程；一阶模型及滑移系数只是等效参数。PID 参数在一种工况可用不表示负载改变后仍满足性能要求。固定种子便于复算，却不能反映全部随机工况；多种子实验仍只检验所设噪声模型。后续应通过阶跃响应辨识执行器参数，通过独立定位标定轮半径和滑移，在保留验证数据的条件下比较预测与实测，再决定模型的适用范围。

## 7. 运行与文档交流

从工程目录进入 `Simulation` 后，可使用以下 PowerShell 命令构建、运行全部示例，并显示默认实验的周期状态：

```powershell
.\build.ps1 -RunAll
.\build\mecanum_sim.exe --config config/default.cfg --output results/demo --realtime
```

构建脚本需要 `gcc` 在 PATH 中，采用 C11、常见警告检查及警告视为错误选项，并自动运行 `--self-test`。`--realtime` 用于按墙钟节拍观察状态，不构成硬实时保证。`--write-config 文件` 生成配置模板，修改后应保留对应版本。配置中的事件路径相对程序当前工作目录解析，因此应从 `Simulation` 运行上述命令；把文件移到其他目录时要同步调整路径。

程序通过 `--edit-report 文件 append|delete|replace 文本 [新文本]` 进行 UTF-8 文本处理，可追加说明、删除指定内容、替换分析文字；删除与替换作用于全部匹配项，未匹配时返回失败并保留原文件。较长文本可通过 `@文本文件` 参数读取。修改报告时应保持单位、数据来源和结论一致，保留自动生成的原始版本便于核查。最终工作报告应交代实验目的、配置、实施步骤、结果指标、异常现象和局限性；设计文档说明模型与实现，二者共同支持复算和答辩。
